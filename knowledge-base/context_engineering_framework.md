## 二、核心痛点：Context污染

### 2.1 什么是Context污染？

**定义**：Agent在执行多个任务时，上下文窗口中残留的前序任务信息对新任务产生干扰，导致性能下降。

**典型场景**：
- 任务A完成后，继续任务B，但A的调试日志占据上下文
- 多任务并行执行，信息相互干扰
- 长对话导致注意力稀释

### 2.2 污染的危害

- **隐性质量退化**：不是报错，而是性能渐进下降
- **认知负载增加**：AI需要在噪声中识别关键信息
- **用户体验下降**：用户感觉"AI越聊越笨"

## 三、现有解决方案分析

### 3.1 方案一：主Agent并行

**做法**：直接在对话框里让AI同时做A、B、C

**适用场景**：
- 需求间高度耦合
- 复杂度低
- 作用于同一文件

**代价**：
- 需求一多就崩
- 认知负载指数级上升
- 每个需求完成质量打折

### 3.2 方案二：主Agent串行

**做法**：做完A，在同一个对话里接着做B，再做C

**现状**：绝大多数人的默认做法

**问题**：
- 每多一轮对话，有效注意力被稀释
- 调试日志、错误信息占据宝贵上下文窗口
- 最危险的方案（温水煮蛙）

### 3.3 方案三：Fork / Rebase

**做法**：做完一个需求后，回滚上下文到干净检查点

**产品实现**：
- **Cursor**：真fork，独立session记录
- **Claude Code**：支持/branch, /fork, /btw, /rewind命令

**优势**：
- 代码保留，上下文重置
- 最接近正解的方案

**局限**：
- 需要手动操作
- 用户需要具备上下文元认知能力
- 门槛较高

### 3.4 方案四：子Agent

**做法**：把不同需求分发给不同Agent，独立上下文

**架构**：
- 主Agent：理解需求、拆分任务
- 子Agent：独立执行，独立上下文

**优势**：
- 独立上下文窗口，避免污染
- 并行执行，效率倍增
- 只汇报结果摘要

**局限**：
- 子Agent无法修改主Agent认知
- 任务拆分本身需要上下文
- 无法解决System Prompt膨胀问题

## 四、AutoContext：创新解决方案

### 4.1 核心理念

**让AI自己管理自己的上下文**，而不是依赖用户的手动操作。

### 4.2 三层架构

#### 4.2.1 第一层：Context感知（Sense）

**功能**：AI自我体检，评估上下文健康度

**评估维度**：
- 当前上下文与新需求的相关性
- 噪声比例（调试日志、已解决错误）
- 信噪比评估

**实现**：无需额外模型调用，AI本身具备判断能力

#### 4.2.2 第二层：Context决策（Decide）

**策略选择**：

| 信噪比 | 策略 | 操作 |
|--------|------|------|
| 高（>80%） | 继续 | 直接执行 |
| 中（40-80%） | 压缩 | 保留相关摘要，丢弃噪声 |
| 低（<40%） | Fork | 创建干净分支 |
| 极低（<10%） | 全新 | 启动新session |

**额外决策**：是否更新外部Context（CLAUDE.md、AGENTS.md）

#### 4.2.3 第三层：Context进化（Evolve）

**学习机制**：
- 积累用户行为模式
- 识别任务关联性
- 自动优化上下文管理策略

**沉淀方式**：将模式写入项目配置文件，形成自进化策略

### 4.3 技术实现

#### 4.3.1 Plugin + Skill架构

**Plugin（插件）**：
- 注册Hook机制（UserPromptSubmit事件）
- 自动触发检测脚本
- 主动介入上下文管理

**Skill（技能）**：
- 提供/auto-context手动入口
- 评估框架和决策逻辑

#### 4.3.2 "笨脚本 + 聪明提示"设计

**脚本功能**：
- 读取transcript文件行数和体积
- 与阈值比较
- 注入<auto-context>提示

**AI判断**：
- Claude本身有完整上下文视野
- 最佳判断"当前上下文是否与新需求相关"

#### 4.3.3 冷却机制

**设计**：同一session每10条消息最多触发一次

**目的**：避免过度干预，保证用户体验

### 4.4 使用方式

#### 4.4.1 完整安装（推荐）

```bash
# Step 1：添加marketplace
/plugin marketplace add lovstudio/claude-code-plugin

# Step 2：安装插件
/plugin install lovstudio@lovstudio-claude-code-plugin
```

**效果**：
- 每次提交prompt时AutoContext自动运行
- 可随时输入/auto-context手动体检

#### 4.4.2 仅安装Skill（手动模式）

```bash
npx skills add lovstudio/skills --skill lovstudio:auto-context
```

**效果**：
- 需要手动输入/auto-context触发
- 适合喜欢完全控制的用户

## 五、实践应用场景

### 5.1 开发场景

**Round 1**：实现用户注册功能
- 上下文充满注册流程细节

**Round 2**：做商品列表页
- AutoContext评估：与注册细节无关，但共享数据库配置
- 自动压缩：保留架构信息，丢弃实现细节

**Round 3**：做支付集成
- AutoContext识别：全新领域，信噪比极低
- 建议Fork：只携带架构概述和API约定

### 5.2 用户体验

| 场景 | 无AutoContext | 有AutoContext |
|------|---------------|---------------|
| 短对话（<40条） | 正常工作 | 完全透明，无干预 |
| 长对话但话题连贯 | 质量逐渐下降 | 检测到健康，正常工作 |
| 长对话且话题漂移 | 性能明显下降 | 建议/fork或/btw |
| 用户主动检查 | 需要手动操作 | 输入/auto-context即可 |

## 六、与相关工具的组合

### 6.1 AI能力释放链路

**三个关键瓶颈**：
1. **输入质量**：/brainstorm工具
2. **上下文质量**：AutoContext工具
3. **推理深度**：/tttt工具

**乘法关系**：
```
AI输出质量 = 输入质量 × 上下文质量 × 推理深度
```

### 6.2 组合工作流

1. **需求厘清**：/brainstorm追问，明确真实需求
2. **上下文管理**：AutoContext监控，保持上下文干净
3. **深度推理**：/tttt一键拉满推理深度
4. **持续优化**：每个环节都在最大化下一步收益

## 七、战略意义

### 7.1 Agent自主性质变

- 从需要用户监管到自我调节
- 手动操作变为自动发生
- 协作者而非工具

### 7.2 长程任务可能

- 突破上下文窗口物理限制
- 通过智能管理实现无限持续工作
- 等效无限窗口

### 7.3 Harness自进化

- 配置文件变成活的系统
- 根据项目演进自动更新
- 经验累积决定能力边界
