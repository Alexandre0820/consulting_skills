# GTM工程化框架：AI驱动的增长系统

## 核心概念

### GTM Repository模型
```
传统模式: 每次重建上下文 → 效果一般 → 无法积累
GTM Repository: 结构化知识库 → 精准输出 → 持续学习
```

### 五层架构详解

#### 第1层: 入口(CLAUDE.md)
**功能**: 会话开始时自动加载
**内容**: ICP摘要、顶级信号、定位、团队、当前优先级
**设计原则**: 2分钟可扫描，详细内容引用到其他文件
**最佳实践**: 每周更新当前优先级，保持与业务同步

#### 第2层: 上下文(6个核心文件)
**profile.md**: 公司概述、产品矩阵、客户画像、参考客户
**icp-definition.md**: 层级定义、明确标准、ICP演变日志
**signal-library.md**: 信号库、检测方法、分值、衰减曲线、消息钩子
**positioning.md**: 价值支柱、信息矩阵、禁忌语言
**competitor-radar.md**: 诚实评估胜负点、模式识别
**personas/**: 买家画像、决策角色、关注点、消息钩子

#### 第3层: 技能(5个核心能力)
**Setup技能**: 自动研究公司，填充70-80%内容
**Account Research**: 完整情报简报、利益相关者地图、推荐角度
**Signal to Sequence**: 完整活动构建、触发逻辑、全序列文案
**ICP Scoring**: 账户评分、层级分配、批量处理
**Weekly Update**: 自动识别过时内容、起草更新建议

#### 第4层: 流程(3个核心流程)
**Enrichment流程**: 数据瀑布、质量阈值、邮件送达基础设施
**Signal Routing流程**: 信号触发决策树、冷却期、分配规则
**Campaign Build流程**: 端到端活动构建、审批、测量

#### 第5层: 输出(持续积累)
**研究简报**: 账户情报、信号评分、推荐策略
**活动简报**: 完整活动方案、序列文案、测量目标
**性能数据**: 回复率、会议率、转换率
**反馈循环**: 输出与上下文对比，持续优化

## 信号工程核心机制

### 信号定义标准
```
完整信号 = 事件类型 + 检测方法 + 时间窗口 + 分值 + 衰减曲线 + 消息钩子
示例: "Series B announced in last 60 days, detected via Crunchbase webhook into Clay, worth 30 points, decay to 15 points after 60 days, message hook: 'Series B is the inflection point where the ops layer either scales or becomes the bottleneck.'"
```

### 信号衰减机制
**原理**: 时间影响信号价值
**实现**: 30点(0-60天) → 15点(60-90天) → 0点(180天)
**价值**: 确保活跃列表反映实际紧迫性，避免历史信号污染

### 信号组合逻辑
**原理**: 信号组合比单独更预测
**实现**: 基础分 + 组合奖励 = 总分
**示例**: Series B(30点) + RevOps招聘(30点) + 组合奖励(20点) = 80点
**洞察**: 预算存在AND组织变革，转换概率更高

## 实施方法论

### 阶段1: 快速启动 (1个下午)
1. **运行Setup技能**: 提供公司域名，Claude自动研究
2. **填充70-80%**: 自动完成基础内容
3. **3分钟精炼**: 人工确认和优化

### 阶段2: 压力测试 (1周)
1. **ICP Scoring测试**: 对当前pipeline评分，识别差距
2. **Account Research测试**: 前10账户深度研究，验证准确性
3. **信号库验证**: 检查信号定义质量和实用性

### 阶段3: 迭代优化 (持续)
1. **活动后更新**: 添加性能数据到信号库
2. **每周更新**: 更新当前优先级和活动状态
3. **季度审查**: 更新ICP定义和演变日志

## 维护节奏

### 每周维护 (5分钟)
- **任务**: 更新CLAUDE.md的Current priorities
- **价值**: 保持整个仓库与当前业务同步
- **频率**: 每周一早晨

### 活动后维护 (15分钟)
- **任务**: 添加结果到campaign输出文件
- **内容**: 回复率、会议率、信号转换、触点响应
- **价值**: 从假设文档变为学习系统

### 赢/输后维护 (30分钟)
- **任务**: 更新competitor-radar.md
- **内容**: AE听到、竞品说法、决策关键点
- **价值**: 实时更新的竞品卡比季度规划更有价值

### 季度维护 (1小时)
- **任务**: 审查ICP定义，添加演变日志
- **内容**: 变化内容、原因、日期
- **价值**: 长期演变记录比当前定义更有洞察

## 自动化集成

### OpenClaw自动化模式
**数据收集**: 自动从外联工具拉取性能指标
**文件更新**: 自动更新信号性能日志和活动结果
**通知机制**: Slack通知总结和决策提示
**人工决策**: 关键判断仍由人类做出

### 自动化优势
- **效率**: 20分钟手动 → 0分钟自动
- **一致性**: 消除人为遗漏
- **实时性**: 及时反馈性能数据
- **规模化**: 支持大规模活动管理

## 组织影响

### 新员工入职革命
**传统模式**: 数周培训和会议
**GTM Repository模式**: 第一天即可理解ICP、信号、定位、优先级
**效果**: 入职时间从数周缩短到数天

### 知识制度化
**传统风险**: 知识随个人离开而消失
**Repository优势**: 知识固化在结构化的文件中
**价值**: 组织记忆不依赖于个人

### 决策一致性
**传统问题**: 不同AE对同一信号处理不一致
**标准化流程**: 明确的决策树和路由规则
**效果**: 提高决策质量和一致性
