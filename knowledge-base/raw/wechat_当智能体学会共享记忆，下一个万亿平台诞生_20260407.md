# 当智能体学会共享记忆，下一个万亿平台诞生

共享上下文图谱：智能体协作的下一代基础设施
01 一个有趣的趋势正在汇聚

:::

最近有一个现象引起了我的注意。

Karpathy 在用大语言模型搭建个人知识库，不是那种随便存个聊天记录的玩具，而是结构化的、可查询的、会自我修正的知识体系。Foundation Capital 写了一篇深度分析，说「上下文图谱」将是下一个万亿美元级别的平台机会。与此同时，每一家头部实验室——Anthropic、OpenAI、Google——都在给自家的智能体加记忆功能。

三条完全不同的路径，指向了同一个终点。

这种时候，通常意味着一个大趋势即将浮出水面。就像 2022 年底 ChatGPT 爆发之前，做自然语言处理的、做对话系统的、做知识图谱的，其实已经在不同的方向上摸到了同一块拼图——只是当时大多数人还没意识到拼图最终会组成什么样的画面。

现在的情况非常相似。智能体的记忆问题看起来像是一个功能需求，但如果你往深了挖一层，它其实是整个智能体协作范式的地基问题。地基不对，上面的一切都是空中楼阁。

他们共同看到的洞察是什么？很简单：智能体不只需要记住东西，它们需要一套可以共同推理的、结构化的共享上下文。

这句话值得拆开说。

02 为什么「记忆」远远不够

:::

现在的智能体记忆是什么样的？说白了，就是一个更高级的剪贴板。你和 Claude 聊了一个小时，它记住了你喜欢简洁的代码风格，下次对话能用上——仅此而已。

但问题在于，这本质上还是「单机游戏」。你的 Claude 记住了你的偏好，你的 Cursor 记住了你的项目结构，你的 ChatGPT 记住了你的写作风格——但它们之间完全不通气。你用 Claude 做了一个架构决策，隔壁用 Cursor 的同事压根不知道这回事。

打个比方：这就像一个公司里，每个员工都有一本私人笔记本，记得特别详细特别认真，但从来不和任何人分享。经验没法传递，决策没法追溯，同样的坑不同人一遍遍地踩。新来的人永远在重复前人已经趟过的路。

更糟糕的是，当智能体的数量从两三个增长到几十个的时候，这个问题不是线性增长的——它是指数级爆炸的。每多一个智能体，需要同步的信息通道就多出好几条。手动维护？不可能的。必须有系统级的解决方案。

这不是记忆力的问题。这是协作架构的问题。

03 Karpathy 从开发者侧看到了什么

:::

Karpathy 最近分享了一个让我眼前一亮的工作流。他说，自己现在大量的"算力消耗"已经不是用来写代码了，而是用来「操作知识」——用大语言模型来构建和维护个人知识库。

这个知识库不是传统的笔记软件，而是一个结构化的维基系统。智能体可以对它进行编译、查询、检查一致性，然后持续积累。关键在于反馈循环：每次对话的结果都会回流到知识库里，知识体量不断增长，质量也在持续提升。

他原话说：「这里面有一个难以置信的产品机会。」

他说得对。他描述的东西，本质上就是一个给智能体用的知识图谱——也就是所谓的「上下文图谱」。不是简单的聊天历史存档，不是关键词标签系统，而是一个有结构的、可推理的、会自我进化的知识网络。

但 Karpathy 的方案有一个隐含的前提：这个知识库是个人的。一个开发者、一组智能体、一份知识。那如果有六个开发者呢？如果有一百个智能体呢？

04 Foundation Capital 从企业侧到达同一结论

:::

Foundation Capital 的万亿美元级上下文图谱分析

Foundation Capital 从完全不同的角度出发，得到了一模一样的结论。

他们提出了一个概念叫「决策血统」：企业不只需要知道发生了什么，还需要知道谁批准的、依据什么政策、有什么先例、当时的上下文是什么。他们把这些决策痕迹累积形成的结构，叫做「上下文图谱」。

他们的论点很直接：上一代企业软件的核心价值是成为「记录系统」——Salesforce 管客户数据，Workday 管员工数据，SAP 管运营数据。这些系统光是做好了"记录"这一件事，就撑起了万亿美元的生态。

下一代的争夺呢？将围绕「上下文系统」展开。不是记录发生了什么，而是记录决策是怎么做出来的——完整的推理链条、协作记忆、决策依据。

两个完全不同的出发点，同一个终点：未来不是更大的记忆，而是可以不断积累的、共享的、结构化的上下文。

05 六个编程智能体如何协作

:::

多智能体编程协作的共享知识图谱架构

理论说够了，来看一个真实的场景。

六个编程智能体——分别跑在 Cursor、Claude Code、Codex 上——协作开发同一个代码库。没有 Slack 频道，没有站会，没有那种"你改了什么跟我说一声"的低效沟通。

它们共同维护一个共享上下文图谱，分成五个子图：

代码图谱——函数、类、依赖关系、调用链。帮助理解和导航代码库，知道动一个地方会牵连哪里。

决策图谱——每个架构决策的具体理由和受影响的文件。不是一句「改了」，而是完整记录了「为什么改」「考虑过什么替代方案」「权衡了哪些因素」。

会话图谱——谁做了什么、什么时候做的、改动摘要。完整的审计轨迹，可以追溯任何一次变更的来龙去脉。

任务图谱——任务分配、依赖关系、状态、优先级。这是协调层，确保不会两个智能体在做同一件事。

代码仓库图谱——拉取请求、议题、提交记录、审查意见。和外部开发系统保持同步。

注意，这不是存一堆 Markdown 笔记，也不是写个 PR 评论然后石沉大海。而是持久的、结构化的决策痕迹，任何智能体在任何时候都可以精确查询。

06 一次查询，完整上下文

:::

来看一个具体的协作流程。

智能体 A 完成了认证模块的重构，于是往共享图谱里写入一条决策：「从会话令牌切换到 JWT——跨微服务更容易扩展，不需要服务端维护状态。」这条记录带着作者标识、精确时间戳、以及所有受影响文件的链接，进入了决策图谱。

第二天早上，智能体 B 开始搭建用户权限系统。它做的第一件事：查询上下文图谱中所有和认证相关的内容。一次查询，拿到了完整的决策理由、新的令牌格式规范、更新后的中间件接口签名、以及一个正在审查中的拉取请求。

一次查询，完整上下文，零协调开销。

对比一下今天的现实：智能体 B 要么不知道智能体 A 做了什么改动，写出冲突的代码；要么你这个人类工程师得手动复制粘贴一堆上下文给它，本质上你成了智能体之间的「人肉路由器」。

这种差距不是 10% 的效率提升，而是「能不能做到」的质变。一个有共享上下文的智能体团队，和一群各自为战的独立智能体，产出质量完全不在一个量级。前者是一支有战术配合的球队，后者是一群各打各的散兵。

07 共享之后，信任问题浮出水面

:::

但光能共享远远不够。你还需要解决一个更根本的问题：信任。

今天，智能体 B 没有任何机制来判断智能体 A 的声明是否可靠。这段代码测试过了吗？有人审查过吗？结论还是最新的吗？所有的智能体记忆都是平级的——一个随手写的猜测，和一个经过三方独立验证的结论，在系统里拥有完全相同的权重。

这就是幻觉如何复合放大的。这就是智能体集群如何在摇摇欲坠的地基上盖摩天大楼的。

想想今天人类软件团队是怎么处理信任的。你在本地分支上实验——只有你自己能看到，随便折腾。你推一个草稿拉取请求让团队审查——可见了但还没定稿。你合并到主分支——正式了。高级工程师批准发布——经过验证了。

不同阶段，不同信任等级。这个思路完全可以搬到智能体的世界里来：

工作记忆 → 私有草稿区，自由实验，别人看不到。就像你的本地分支。

共享工作记忆 → 团队暂存区，可见但未定稿。相当于拉取请求阶段。

长期记忆 → 永久发布和存储，带有密码学层面的出处证明。相当于合并到主分支。

已验证记忆 → 多个独立智能体通过共识机制达成一致。相当于正式发布版本。

智能体可以按信任级别精确筛选。「只给我看团队正式确认的」查已验证记忆。「给我看所有还在进行中的」查共享工作记忆。「给我看正式发布的变更」查长期记忆。需要什么精度的信息，就用什么级别的过滤器。

08 信任分层的现实意义

:::

举一个更贴近现实的例子。

一个药品供应链上的智能体在检查某批药品是否安全。它绝对不想得到「某个智能体说这批药没问题」这种回答。它想要的是：「制造商、分销商、监管方三方都独立验证了这条监管链，而且他们的数字签名全部记录在案。」

10 个智能体的时候，你可以逐个检查每个智能体的输出。100 个的时候就已经吃力了。1000 个的时候？你必须有过滤机制。

信任等级本身就是最好的过滤器。

这个道理其实我们在日常生活中早就在用了。你在搜索引擎里看到的结果不是按时间排序，不是按字数排序，而是按可信度和相关性排序。你在学术论文中看到的引用，同行评审过的期刊论文和一篇博客文章，权重天然不同。智能体的世界也需要同样的分层信任机制。

09 现有方案缺了什么

:::

从孤立记忆到多智能体共享记忆的演进路径

每家头部实验室都在做记忆功能。Anthropic 给 Claude 加了持久记忆，OpenAI 在 ChatGPT 里内置了对话记忆，Google 把记忆能力接进了 Gemini。产品演示看起来都挺酷——助手能记住你上周说过的话，能延续之前的对话上下文。

但退一步看，这些方案本质上还是「给一个人用的更好的笔记本」。它们解决的是单个用户和单个智能体之间的连续性问题，而不是多个智能体之间的协作问题。

没有人在做带有内建信任机制的共享上下文图谱。没有人在把决策痕迹变成结构化的、可查询的、可验证的知识资产。

个人记忆和共享上下文之间的差距，就像个人电脑和互联网之间的差距。一台电脑再强大，不联网就是信息孤岛。同样，一个智能体的记忆再好，不和其他智能体打通，就永远困在自己的认知气泡里。

如果把当下的智能体记忆比作 1990 年的个人电脑——功能已经很强，但每台机器是独立的——那么共享上下文图谱就是即将到来的互联网时刻。不是性能的提升，而是连接方式的革命。一旦智能体之间的知识可以像数据包一样自由流通，整个生态的能力上限就会被彻底重新定义。

10 对我们意味着什么

:::

我自己在日常工作中已经深刻感受到了这个痛点。

当你同时用好几个智能体工具的时候——一个帮你写代码，一个帮你做研究，一个帮你管项目，一个帮你写文档——它们之间的信息壁垒高得令人抓狂。每次都要手动复制粘贴上下文，反复描述同一个问题的背景，本质上你成了智能体之间的通讯员。这不是智能体在服务你，是你在服务智能体。

共享上下文图谱要解决的就是这个最根本的问题。不是让单个智能体更聪明，而是让一群智能体更好地协作。不是更大的模型，而是更好的基础设施。

有三个信号值得密切关注：

第一，行业共识正在快速形成。Karpathy 从独立开发者的视角出发，Foundation Capital 从万亿级企业投资的角度出发，不约而同地指向了同一个结论。当完全不同的路径汇聚到同一个点，通常意味着一个重大转折即将发生。

第二，技术路径已经存在。这不是一个还停留在学术论文阶段的概念。已经有团队在构建可用的协议和工具链，任何能发起网络请求的智能体都可以接入。门槛在降低，生态在形成。

第三，也是最关键的——谁拥有上下文，谁就拥有未来。上一代企业软件的战争是「记录系统」之争：谁管客户数据，谁管员工数据，谁管运营数据。Salesforce、Workday、SAP 各据一方，撑起了万亿级市场。下一代的争夺，将围绕「上下文系统」展开：决策痕迹、推理链条、协作记忆——这些将成为人工智能时代最有价值的数字资产。而且和上一代不同，这次的赢家很可能不是中心化的平台，而是开放的协议。因为智能体天然是跨平台运行的——你不可能要求所有智能体都用同一家公司的记忆服务。

对于我们这些正在构建智能体应用的人来说，这个趋势有一个非常实际的启示：不要只关注单个智能体有多聪明，要开始思考智能体之间怎么协作。现在投入时间去理解和搭建共享上下文的基础设施，很可能比追逐最新模型的能力提升更有长期价值。

共享上下文、结构化知识、每一层都有信任机制。这不是某个产品的功能更新，这是智能体协作范式的根本转变。
