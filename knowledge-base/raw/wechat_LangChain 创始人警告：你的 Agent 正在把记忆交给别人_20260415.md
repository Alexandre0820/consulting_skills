# LangChain 创始人警告：你的 Agent 正在把记忆交给别人

**来源**: Sense AI (微信公众号)
**抓取日期**: 2026-04-15
**原文链接**: https://mp.weixin.qq.com/s/96q1YMhdFE64l_QOX65ryg

## 核心结论

### Agent外壳与记忆的锁定效应
- **外壳即记忆**: 记忆不是插件，而是外壳的核心职责
- **锁定效应**: 记忆制造锁定效应，是平台方的护城河
- **封闭外壳代价**: 轻度(状态在对方服务器)、中度(记忆格式未知)、最坏(零可见零控制)

### 开放外壳的解法
- **开源**: 外壳管理记忆的代码可读，没有黑盒
- **模型无关**: 可更换模型，记忆不丢失
- **开放标准**: 采用agents.md、skills等标准格式
- **存储自选**: 自选数据库，不被锁定
- **可自部署**: 不依赖平台托管

### 对开发者的启示
- **个人用户**: Claude Code记忆在本地，目前可控
- **产品开发者**: 必须考虑记忆主权和迁移能力
- **长期价值**: 记忆是差异化体验的真正来源和竞争壁垒

## 详细分析

### 01 外壳是什么

**Agent外壳定义**:
- 包裹着模型、让它能够持续行动的那一整层系统
- 不是模型本身，但没有它，模型就只是一个问答机器

**外壳负责的事情**:
- 把提示词、记忆、技能信息注入上下文
- 管理工具调用的控制循环
- 把工具执行结果反馈回模型
- 把观察输入(浏览器截图、测试日志、文件内容)
- 把中间状态持久化到文件系统或Git

**主流外壳案例**: Claude Code、Deep Agents、Codex、OpenCode、Letta Code

### 02 外壳即记忆

**记忆不是插件**:
- 管理上下文(记忆)是外壳最核心的职责之一
- 记忆和外壳是一体的，不是可独立配置的参数

**记忆管理决策在外壳层面**:
- AGENTS.md或CLAUDE.md文件怎么加载进上下文？加载多少？什么时候刷新？
- 技能元数据怎么呈现给Agent？
- Agent能不能修改自己的系统指令？谁来决定边界？
- 上下文压缩时，什么内容会被丢弃，什么必须保留？
- 历史交互记录是否被存储？是否可以被查询？
- 当前工作目录怎么呈现给Agent？

### 03 封闭外壳的代价

**三个严重等级**:

| 严重程度 | 典型场景 | 后果 |
|----------|----------|------|
| 轻度 | 有状态API(OpenAI Responses API、Anthropic服务端压缩) | 状态存在对方服务器，想换模型、延续旧线程做不到 |
| 中度 | 封闭外壳(如Claude Agent SDK，底层是非开源的Claude Code) | 外壳如何管理记忆完全不知道，记忆格式未知，无法迁移 |
| 最坏 | 整个外壳含长期记忆全藏在API后面(如Claude Managed Agents) | 零可见、零控制，连记忆长什么样都不知道，更别提迁移 |

**案例**: Claude Managed Agents把一切都封进API背后，外壳怎么运转、记忆存储格式、压缩摘要生成全是黑箱。

### 04 平台的算盘

**锁定效应战略**:
- 记忆制造锁定效应，是平台方仅凭模型本身没法得到的
- 更换模型提供商比较容易(无状态接口)，但有了状态和记忆后迁移极其痛苦

**记忆的价值**:
- 陪伴用户半年的Agent积累了用户的偏好、沟通风格、工作习惯
- 这些是独一无二的数据资产，迁移意味着失去它们

**锁定策略推进**:
- 趁着开发者还没明白记忆的价值，趁着行业还没有形成开放标准
- 等开发者意识到问题时，六个月的记忆已经沉淀，迁移成本足以让开发者选择留下

### 05 那封邮件的故事

**Harrison的个人经历**:
- 在Fleet平台上使用邮件助理，几个月来积累了个人偏好和习惯
- Agent被意外删除后，重新建立需要重新教导所有偏好
- 体验差异巨大，真实感受到了记忆的价值和粘性

**关键启示**:
- 在自家平台上，记忆完全开放，知道存在哪里，格式是什么
- 如果是在Claude Managed Agents上，删除后没有任何方法恢复，甚至不知道记忆长什么样

### 06 记忆还很早

**当前局限**:
- Agent记忆技术还非常早期
- 长期记忆往往不在MVP里，行业还没有形成统一的记忆抽象和最佳实践
- 没有公认的记忆数据格式，没有跨外壳的迁移协议

**平台方策略**:
- 趁着开发者还没明白记忆的价值，趁着行业还没有形成开放标准，先锁定开发者
- 等开发者意识到问题时，记忆已经沉淀，迁移成本足以让开发者选择留下

### 07 开放的解法

**理想开放外壳的特征**:
- **开源**: 外壳管理记忆的代码可读，没有黑盒
- **模型无关**: 今天用Claude，明天换Gemini，记忆不丢失
- **遵循开放标准**: 采用agents.md、skills等行业共识格式
- **存储自选**: 接MongoDB、PostgreSQL还是Redis，由开发者决定
- **可自部署**: 不依赖平台托管，可以跑在开发者自己的云或服务器上

**Deep Agents的实践**: Harrison推行的开放外壳解决方案

### 08 对我们意味着什么

**个人用户**:
- Claude Code记忆在本地文件系统，可见、可控、可备份
- 知道CLAUDE.md是什么，可以编辑、版本控制、迁移
- 但Anthropic已在推进服务端上下文管理、服务端压缩，值得持续关注

**产品开发者**:
- 必须认真考虑外壳选择、记忆存储位置和格式、迁移能力
- 用户用了Agent半年积累的偏好、数据、记忆——这是属于谁的？
- 没有记忆，Agent谁都能复制；有了记忆，拥有了专有数据集和竞争壁垒

**本质**: Agent时代的数据主权之争刚刚开始，护城河不是用户数量也不是功能多寡，而是每个用户在使用过程中沉淀下来的、只属于这个Agent产品的记忆。
