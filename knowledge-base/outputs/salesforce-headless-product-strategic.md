## 一、核心洞察

### 1.1 Salesforce的战略信号

**表面**：去掉界面，开放API
**实质**：宣布价值从界面层转移到数据层

**Seema Amble的质疑**：Salesforce真的有专有数据吗？

### 1.2 护城河五维评分体系

| 维度 | 旧时代权重 | Agent时代权重变化 |
|------|-----------|----------------|
| 访问频率 | ⬆️ 越高越强 | ⬇️ 肌肉记忆失效 |
| 读写依赖 | ⬆️ 双向越强 | ⬇️ Agent可随时切换 |
| 隐性流程 | ⬆️ 越复杂越强 | ⬆️ 需要显式定义 |
| 网络效应 | 几乎没用 | ⬆️ 可能在Agent协作中复活 |
| 合规绑定 | ⬆️ 越强越稳 | 不变（最强护城河） |

**迁移成本谱**：ATS(低) → CRM(高) → ERP(极端)

## 二、AI时代的护城河重构

### 2.1 正在失效的旧护城河

| 旧护城河 | 失效原因 |
|---------|---------|
| 肌肉记忆 | Agent无"习惯"，24/7运行 |
| 培训成本 | Agent不需要培训 |
| 个人偏好 | 对Agent不存在 |
| 数据导出难度 | AI让导出/重建变得容易 |

### 2.2 新护城河：数据排放（Data Exhaust）

**定义**：不是客户导入的数据，而是产品在业务流程中"造"出来的数据

**三要素**：
1. 行为模式（用户/Agent做了什么）
2. 执行轨迹（动作→结果的反馈循环）
3. 上下文传递（多系统协作时的环境信息）

**判断标准**：如果用户迁走，能带走的数据有多少是真正有价值、无法复制的？

### 2.3 四层护城河

```
Layer 4: 现实世界执行  ← Agent碰不着
         （DoorDash模式：调度/物流/现场服务）

Layer 3: 网络效应  ← 在Agent协作中复活
         （多方协调的中间节点）

Layer 2: 数据排放  ← 最强的软件护城河
         （行为数据/执行轨迹/上下文）

Layer 1: 受保护数据  ← 不变的硬护城河
         （医疗/工业/金融监管数据）

Layer 0: 界面习惯  ← 正在失效
         （肌肉记忆/培训成本）
```

## 三、Schema与权限的底层重写

### 3.1 新数据模型

| 旧对象 | 新对象 |
|--------|--------|
| Opportunities | Tasks（任务状态） |
| Tickets | Intents（意图） |
| Candidates | Threads（对话线程） |
| — | Policies（策略规则） |
| — | Outcomes（结果反馈） |

**类比**：把为汽车驾驶员设计的高速公路硬塞给无人驾驶车队用

### 3.2 新权限模型

```
旧权限：人可以做什么
新权限：哪个Agent → 代表哪个人 → 在什么策略下 → 经什么审批 → 带什么审计轨迹 → 如何回滚
```

## 五、风险提示

- **时效性风险**：Agent时代护城河边界还在移动，现在的地图明年可能要重画
- **Salesforce特异性**：Salesforce案例不代表所有SaaS，需谨慎外推
- **技术债现实**：Schema和权限重写成本极高，不是所有公司都能承受
- **合规数据陷阱**：受保护数据的护城河优势假设监管环境不变
